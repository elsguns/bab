Ontbrekend briefje uitzoeken

Wat dit is. Je selecteerde zes pickbonnen en kreeg vijf briefjes. Deze serveractie loopt de vier redenen af waarom een klant van de Productenmatrix kan wegvallen, en zegt welke het is.

1. De vier mogelijke oorzaken

  1. Geen verkooporder aan de pickbon. Het raster komt uit de orderlijnen, niet uit de bon. Zonder order valt er niets te tekenen.
  2. “Variantrasters afdrukken” staat uit op het order. Een standaard Odoo-vinkje op de verkooporder; staat het uit, dan slaat het rapport dat order over.
  3. Maar één orderlijn voor dat hoofdproduct. Dit is de meest waarschijnlijke. Het rapport maakt pas een raster vanaf twee lijnen — bestelt de klant van 53212 Mantel maar één maat, dan verdwijnt hij volledig van de afdruk.
  4. Niets gepickt. Sinds de aanpassing van gisteren tonen de briefjes de aantallen van de bon zelf. Staat alles op nul, dan blijft er niets over om af te drukken.

2. De serveractie

Instellingen → Technisch → Serveracties → Nieuw.

Naam* Ontbrekend briefje uitzoeken
ModelServeractie (ir.actions.server)
TypePython-code uitvoeren

Zet bovenaan de code het verkooporder van de klant die ontbreekt — voor Textilhaus Kaulmann is dat S01829. De actie zoekt zelf de bijhorende pickbon(nen).

# Vul hier het verkooporder in van de klant die ontbreekt.
ORDER = 'S01829'

regels = []
order = env['sale.order'].search([('name', '=', ORDER)], limit=1)
if not order:
    raise UserError("Verkooporder %s niet gevonden." % ORDER)
regels.append("ORDER %s | klant=%s | rasters afdrukken=%s" % (
    order.name, order.partner_id.display_name, order.report_grids))

# 1. Welke pickbonnen horen bij dit order?
bonnen = order.picking_ids.filtered(
    lambda b: b.picking_type_id == b.picking_type_id.warehouse_id.pick_type_id)
if not bonnen:
    regels.append("1. GEEN pickbon voor dit order -- dan valt er ook niets af te drukken.")
for bon in bonnen:
    regels.append("1. %s | status=%s" % (bon.name, bon.state))

# 2. Hoeveel orderlijnen per hoofdproduct? Bij een enkele lijn valt het blok weg.
lijnen = order.order_line.filtered('is_configurable_product')
per_tmpl = {}
for lijn in lijnen:
    per_tmpl.setdefault(lijn.product_template_id, 0)
    per_tmpl[lijn.product_template_id] += 1
if not per_tmpl:
    regels.append("2. Geen enkele configureerbare orderlijn (product zonder varianten?)")
for tmpl in per_tmpl:
    regels.append("2. %s: %d orderlijn(en)%s" % (
        tmpl.display_name, per_tmpl[tmpl],
        "  <-- TE WEINIG, blok valt weg" if per_tmpl[tmpl] <= 1 else ""))

# 3. Wat staat er op de bon zelf? Enkel wat gepickt is, komt op het briefje.
for bon in bonnen:
    gepickt = 0
    for move in bon.move_ids:
        if move.state != 'cancel':
            gepickt += move.quantity
    regels.append("3. %s: totaal gepickt = %s" % (bon.name, gepickt))

# 4. En wat levert het rapport uiteindelijk op?
for bon in bonnen:
    blokken = bon._get_matrix_blocks()
    regels.append("4. %s: %d blok(ken) %s" % (
        bon.name, len(blokken), [b['grid']['header'][0]['name'] for b in blokken]))

log("\n".join(regels))
  • Serveractie aangemaakt, ORDER op het juiste verkooporder gezet.
  • Op Uitvoeren geklikt en het resultaat gelezen in Instellingen → Technisch → Logboek.
  • Serveractie verwijderd.

4. Als het de enkele orderlijn is

Dan is het geen fout maar een keuze die indertijd in de module gemaakt is: een raster van één cel werd als zinloos beschouwd. Dat is te herzien — het briefje toont dan gewoon een tabel met één maat erin, wat voor het magazijn nog altijd bruikbaar is, want het draagt de klantnaam en het ordernummer.

Het is wel een codewijziging, dus ze komt mee met de volgende uitrol. Zeg maar of je dat wil, dan pas ik het aan.
