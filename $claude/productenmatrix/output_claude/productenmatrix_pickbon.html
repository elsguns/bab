Productenmatrix afdrukken op de pickbon — zonder module-update

Alles hieronder gebeurt in de database, via de interface. Er wordt geen enkel record van bab_stock_delivery gewijzigd, dus een latere module-update kan dit niet terugdraaien. De code om te plakken staat telkens bij de stap zelf.

1. Het probleem

De guard in report_delivery_matrix.py weigert alles wat niet uitgaand is:

wrong_type = pickings.filtered(lambda p: p.picking_type_id.code != 'outgoing')
if wrong_type:
    raise UserError(...)

Sinds de pickstap is ingeschoven hoort de matrix op de pickbon, en die heeft code = 'internal'. Elke poging eindigt dus in de foutmelding — nagegaan op WH/PICK/00001. De juiste voorwaarde is: het picktype van het eigen magazijn, én status Klaar.

2. Waarom langs een tweede rapport

_get_report_values is Python in de module; er bestaat geen databaserij die die methode bevat, dus rechtstreeks aanpassen kan niet. Wat wél helpt, is hoe Odoo een rapport rendert:

def _get_rendering_context_model(self, report):
    report_model_name = 'report.%s' % report.report_name
    return self.env.get(report_model_name)          # None -> generieke context

Een rapport waarvan de report_name géén overeenkomstig model report.<naam> heeft, valt terug op een generieke context — en loopt dus nooit door de guard. Een tweede rapport met een eigen sjabloonnaam, waarbij dat sjabloon niets anders doet dan het bestaande aanroepen, geeft exact dezelfde afdruk zonder de blokkade. De nieuwe voorwaarde komt in de serveractie te staan, en die staat wél in de database.

3. Opzet

3a. Sjabloon + rapport

Het veld key van een weergave staat niet op het formulier, dus dit gaat via code. Instellingen → Technisch → Serveracties → Nieuw:

Actienaam* Productenmatrix (pickbon) aanmaken
ModelServeractie (ir.actions.server)
TypeCode uitvoeren, met onderstaande code
# Eenmalige opzet: sjabloon + rapport voor de Productenmatrix op de pickbon.
#
# Plak dit in een SERVERACTIE (Instellingen -> Technisch -> Serveracties) met
# model "Serveractie" (ir.actions.server) en type "Code uitvoeren". Enkel met
# dat model toont Odoo 18 de knop "Uitvoeren" bovenaan het formulier.
# Twee keer draaien is veilig: bestaat het al, dan maakt de code niets bij.
# Verwijder de serveractie nadien.

TEMPLATE = 'bab_stock_delivery.report_deliveryslip_matrix_pick'

# 1. Een QWeb-sjabloon dat niets anders doet dan het bestaande sjabloon
#    aanroepen. Het draagt een ANDERE naam, zodat Odoo geen model
#    report.<naam> vindt en de guard uit report_delivery_matrix.py dus niet
#    doorlopen wordt. Aanmaken via code omdat het veld "key" niet op het
#    weergaveformulier staat.
view = env['ir.ui.view'].search([('key', '=', TEMPLATE)], limit=1)
if not view:
    view = env['ir.ui.view'].create({
        'name': 'Productenmatrix (pickbon)',
        'type': 'qweb',
        'key': TEMPLATE,
        'arch_db': '<t t-name="' + TEMPLATE + '"><t t-call="bab_stock_delivery.report_deliveryslip_matrix"/></t>',
    })

# 2. Het rapport: een kopie van het bestaande, zodat papierformaat en
#    bestandsnaam meekomen, maar wijzend naar het nieuwe sjabloon.
report = env['ir.actions.report'].search([('report_name', '=', TEMPLATE)], limit=1)
if not report:
    report = env.ref('bab_stock_delivery.action_report_delivery_matrix').copy({
        'name': 'Productenmatrix (pickbon)',
        'report_name': TEMPLATE,
        'report_file': TEMPLATE,
    })

log("Productenmatrix (pickbon): view %s, rapport %s" % (view.id, report.id))

Dat vreemd ogende model is geen vergissing. Odoo 18 toont de knop Uitvoeren enkel onder deze voorwaarde:

<button name="run" string="Run" type="object"
        invisible="model_name != 'ir.actions.server' or state != 'code'"/>

Met Serveractie als model krijg je die knop dus wél, en je hebt geen record nodig om de actie op te draaien. (In Odoo 19 is de knop verdwenen; daar is een geplande actie met Handmatig uitvoeren de uitweg.)

  • Serveractie aangemaakt met de code erin.
  • Klik Uitvoeren bovenaan het formulier.
  • Controleer in Instellingen → Technisch → Logboek de regel Productenmatrix (pickbon): view … rapport ….
  • Verwijder de serveractie.

De code werkt zonder neveneffect bij herhaling: hij zoekt eerst en maakt enkel aan wat ontbreekt. Twee keer draaien levert geen dubbels op — nagegaan in de werkkopie.

3b. De afdrukactie

Instellingen → Technisch → Serveracties → Nieuw:

Actienaam* Productenmatrix (pickbon)
ModelOverboeking (stock.picking)
TypeCode uitvoeren, met onderstaande code
# * Productenmatrix (pickbon)
#
# Code van de contextuele serveractie op overboekingen (model stock.picking).
# Vervangt tijdelijk "* Productenmatrix": de guard in de module
# (bab_stock_delivery/models/report_delivery_matrix.py) laat enkel uitgaande
# leveringen door, terwijl de matrix op de pickstap hoort. Zolang de module niet
# aangepast kan worden, print deze actie via een tweede rapport dat die guard
# niet doorloopt.
#
# Deze variant WEIGERT een herdruk. De tweede serveractie
# "* Productenmatrix (pickbon) - herdruk" bevat exact dezelfde code, met
# ALLOW_REPRINT op True. Pas je hier iets aan, pas het daar dan ook aan.

ALLOW_REPRINT = False

report = env['ir.actions.report'].search(
    [('report_name', '=', 'bab_stock_delivery.report_deliveryslip_matrix_pick')], limit=1)
if not report:
    raise UserError(
        "Het rapport 'Productenmatrix (pickbon)' bestaat nog niet. "
        "Draai eerst de geplande actie die het aanmaakt.")

# Het picktype via het magazijn van de overboeking zelf opvragen in plaats van
# een vast ID: Babimex, bol.com en Vasa hebben elk hun eigen picktype.
wrong = []
for picking in records:
    if picking.picking_type_id != picking.picking_type_id.warehouse_id.pick_type_id:
        wrong.append("%s (geen pickbon)" % picking.name)
    elif picking.state != 'done':
        wrong.append("%s (nog niet klaar)" % picking.name)
    elif picking.matrix_printed and not ALLOW_REPRINT:
        wrong.append("%s (al afgedrukt)" % picking.name)

if wrong:
    message = "De Productenmatrix kan niet afgedrukt worden voor:\n" + "\n".join(wrong)
    if not ALLOW_REPRINT and any(p.matrix_printed for p in records):
        message += ("\n\nGebruik '* Productenmatrix (pickbon) - herdruk' "
                    "om bewust opnieuw af te drukken.")
    raise UserError(message)

# Dezelfde vlag als de module bij het renderen zet, zodat blijft bijgehouden wat
# al afgedrukt is -- ook wanneer de module later wel aangepast kan worden.
records.filtered(lambda p: not p.matrix_printed).write({'matrix_printed': True})

action = report.report_action(records)

Het picktype wordt via het magazijn van de overboeking zelf opgehaald, niet via een vast ID — Babimex, bol.com en Vasa hebben elk hun eigen picktype.

Daarnaast weigert deze actie een herdruk: een pickbon waarvan matrix_printed al aanstaat, komt in dezelfde foutmelding terecht, met een verwijzing naar de herdrukactie uit stap 3c.

  • Serveractie opgeslagen.
  • Klik Maak contextuele actie, zodat ze in het Actie-menu van de overboekingen verschijnt.

3c. De herdrukactie

Nog een serveractie, met exact dezelfde code op één regel na:

Actienaam* Productenmatrix (pickbon) - herdruk
ModelOverboeking (stock.picking)
TypeCode uitvoeren, met onderstaande code — enkel ALLOW_REPRINT verschilt van stap 3b
# * Productenmatrix (pickbon) - herdruk
#
# Exact dezelfde code als "* Productenmatrix (pickbon)", met ALLOW_REPRINT op
# True: deze variant drukt ook af wat al eens afgedrukt is. De controle op
# picktype en status blijft wel gelden.
#
# Bedoeld als bewuste tweede stap: de gewone actie weigert een herdruk en
# verwijst naar deze. Pas je iets aan in de gewone actie, pas het hier dan ook
# aan.

ALLOW_REPRINT = True

report = env['ir.actions.report'].search(
    [('report_name', '=', 'bab_stock_delivery.report_deliveryslip_matrix_pick')], limit=1)
if not report:
    raise UserError(
        "Het rapport 'Productenmatrix (pickbon)' bestaat nog niet. "
        "Draai eerst de geplande actie die het aanmaakt.")

# Het picktype via het magazijn van de overboeking zelf opvragen in plaats van
# een vast ID: Babimex, bol.com en Vasa hebben elk hun eigen picktype.
wrong = []
for picking in records:
    if picking.picking_type_id != picking.picking_type_id.warehouse_id.pick_type_id:
        wrong.append("%s (geen pickbon)" % picking.name)

if wrong:

    if not ALLOW_REPRINT and any(p.matrix_printed for p in records):
        message += ("\n\nGebruik '* Productenmatrix (pickbon) - herdruk' "
                    "om bewust opnieuw af te drukken.")
    raise UserError(message)

# Dezelfde vlag als de module bij het renderen zet, zodat blijft bijgehouden wat

De controle op picktype en status geldt hier onverkort; enkel de herdrukblokkade valt weg.

  • Serveractie opgeslagen en contextueel gemaakt.
  • Pas je later iets aan in de ene actie, doe het dan ook in de andere — de twee bevatten dezelfde code.

3d. De oude actie opzijzetten

  • Open * Productenmatrix in de serveracties en klik Contextuele actie verwijderen, zodat niemand nog per ongeluk de oude, blokkerende weg neemt.

Verwijder de oude serveractie niet: ze hoort bij de module en komt bij elke module-update terug. Enkel de binding weghalen volstaat, en dat blijft ook na een update zo — het is de module zelf die de binding leeg zet.

4. Herdruk en wat je inlevert

Wat al afgedrukt is, blijft gewoon bijgehouden. matrix_printed is een veld op stock.picking, geen onderdeel van de rapportcode; de serveractie zet het waar de module het vroeger bij het renderen zette.

Wat wél wegvalt is de bevestigingsdialoog vóór een herdruk. De wizard bab.matrix.reprint.confirm roept in zijn knoppen action_print_matrix() aan — de oude weg, die weer op de guard botst — en een wizard valt niet vanuit de database te maken. In de plaats komt een strengere opzet:

* Productenmatrix (pickbon) Weigert met de namen van de al afgedrukte pickbonnen en verwijst naar de herdrukactie.
* Productenmatrix (pickbon) - herdruk Drukt bewust opnieuw af. Picktype en status worden nog altijd gecontroleerd.

Een herdruk vergt dus een tweede, uitdrukkelijke handeling in plaats van één klik in een dialoogvenster.

5. Testen

  • Een klare pickbon → Actie → * Productenmatrix (pickbon) geeft de PDF, en matrix_printed staat nadien aan.
  • Dezelfde pickbon nog eens → melding “al afgedrukt”, met de verwijzing naar de herdrukactie.
  • Herdrukactie op diezelfde pickbon → geeft wél de PDF.
  • Een pickbon in Gereed → melding “nog niet klaar”, geen PDF. Ook via de herdrukactie.
  • Een uitgaande levering → melding “geen pickbon”, geen PDF.
  • Meerdere pickbonnen tegelijk vanuit de lijst.

Alle gevallen zijn in de werkkopie doorlopen (WH/PICK/00045 klaar, WH/PICK/00110 gereed, WH/OUT/00411 uitgaand) en gaven het verwachte resultaat; de PDF van de klare pickbon bevatte een volwaardige matrix van 19 kB.

6. Nadien: de module patchen

Zodra bab_stock_delivery weer uitgerold kan worden, hoort de voorwaarde terug in report_delivery_matrix.py — picktype van het eigen magazijn én status done — en mag deze omweg weg.

  • Guard in de module gecorrigeerd en uitgerold.
  • Serveracties * Productenmatrix (pickbon) en … - herdruk verwijderd.
  • Rapport en weergave …report_deliveryslip_matrix_pick verwijderd.
  • Binding van * Productenmatrix hersteld.
