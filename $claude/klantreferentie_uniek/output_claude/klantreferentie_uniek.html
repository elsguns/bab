“Klant + referentie uniek” aanpassen

BAB · Odoo 18.0 (Odoo.sh) · automatiseringsregel op sale.order · genoteerd 2026-08-10

Doel

De regel blokkeert vandaag het dupliceren van een verkooporder. Na deze aanpassing:

SituatieNuNa de aanpassing
Order dupliceren (kopie krijgt geen referentie)GeblokkeerdToegelaten
Zelfde referentie, zelfde klant, lopend orderGeblokkeerdGeblokkeerd
Zelfde referentie in andere hoofdletters, of met een spatie erachterToegelatenGeblokkeerd
Zelfde referentie, maar het andere order is geannuleerdGeblokkeerdToegelaten
FoutmeldingZonder ordernummerMet ordernummer van het botsende order

Het is een wijziging in de database, geen code — dus rechtstreeks in productie, zonder deploy.

Waarom kopiëren stukloopt

Odoo's veld client_order_ref (“Referentie klant”) staat op copy=False: bij dupliceren komt de kopie er zonder referentie uit. De regel draait bij het aanmaken en zoekt dan op:

('client_order_ref', '=', False)

En dat matcht elk ander order van dezelfde klant zonder referentie. Bijna altijd is er zo eentje, dus valt de kopie meteen tegen de foutmelding aan — met “None” als referentie in de tekst.

De triggervelden (client_order_ref, team_id) beperken enkel het bijwerken van bestaande orders. Bij het aanmaken draait de regel altijd, welke velden je ook opgeeft. Daarom helpt het niet om aan de triggervelden te sleutelen.

Aan die vier bovenste regels verandert niets. Enkel de Python-code van de actie wordt vervangen.

De nieuwe code

for record in records.filtered('client_order_ref'):
    ref = record.client_order_ref.strip()
    duplicate = env['sale.order'].search([
        ('partner_id', '=', record.partner_id.id),
        ('company_id', '=', record.company_id.id),
        ('client_order_ref', '=ilike', ref),
        ('state', '!=', 'cancel'),
        ('id', '!=', record.id),
    ]).filtered(lambda o: (o.client_order_ref or '').strip().lower() == ref.lower())[:1]
    if duplicate:
        raise UserError(
            f"De klantreferentie '{ref}' bestaat al voor klant "
            f"'{record.partner_id.name}' (order {duplicate.name}). Deze moet uniek zijn."
        )

Vooraf getest op de werkkopie bab18-20260618: de code compileert binnen safe_eval (server-acties draaien in een beperkte Python-omgeving) en de vier testgevallen hieronder gedragen zich zoals beschreven.

Aanpassen in productie

Let op de inspringing. Het codeveld is gewone Python: plak de code zonder extra spaties vooraan, anders krijg je een IndentationError bij het opslaan.

Verifiëren — vier testgevallen

Neem een klant met minstens één order mét referentie. Doe dit bij voorkeur op een order dat je nadien mag wissen.

Webshoporders (team Website) blijven volledig buiten schot — die zitten niet in het domein van de regel.

Terugdraaien

Ging er iets mis, plak dan de originele code terug:

for record in records:
    duplicate = env['sale.order'].search([
        ('partner_id', '=', record.partner_id.id),
        ('client_order_ref', '=', record.client_order_ref),
        ('id', '!=', record.id)
    ], limit=1)
    if duplicate:
        raise UserError(
            f"De klantreferentie '{record.client_order_ref}' bestaat al voor klant '{record.partner_id.name}'. Deze moet uniek zijn."
        )

Moet je dringend verder kunnen werken en lukt de aanpassing niet meteen, dan kan je de regel ook gewoon uitvinken (Actief) — dan valt de controle helemaal weg tot je terug bent.

Bestaande dubbele referenties

In de werkkopie staan 6 klantparen (12 orders) die vandaag al dezelfde referentie delen — o.a. “79106”, “79107”, “réassort”, “lijsten”, “afhaling”. Bij vijf ervan zitten beide orders in hetzelfde bedrijf; het zesde paar loopt over twee bedrijven en botst dus niet meer. Die dubbels zijn ontstaan vóór de regel bestond (17 februari 2026) of terwijl ze uit stond.

De nieuwe code ruimt die niet op en gaat er ook niet over klagen: de regel draait enkel wanneer je een order aanmaakt of de klantreferentie/het verkoopteam wijzigt. Pas wanneer iemand de referentie van zo'n order aanraakt, botst hij op de melding. Dat is dan het moment om te beslissen welke van de twee de referentie houdt.

Aandachtspunten

De vervangroutine zet de referentie wél over

Het script order_vervangen.py kopieert de klantreferentie bewust naar het nieuwe order en zet er een x achter op het oude. Dat blijft werken zoals het is — maar als dat oude order níet geannuleerd wordt, botsen ze op elkaar.

Odoo heeft zelf ook een duplicaatcontrole

Sinds versie 17 toont Odoo standaard een waarschuwingsbalk op het orderformulier bij dezelfde klant, referentie, orderdatum én bron. Die blokkeert niet en is enger dan deze regel — ze vervangt dit dus niet, maar je zal ze af en toe naast de foutmelding zien staan.

Waarom een automatiseringsregel en geen SQL-constraint

Een echte uniciteitsindex op (klant + referentie) zou geen lege referenties, geen geannuleerde orders en geen webshoporders kunnen uitzonderen, en zou ook bestaande data blokkeren. De regel houdt die uitzonderingen leesbaar en aanpasbaar zonder module.
