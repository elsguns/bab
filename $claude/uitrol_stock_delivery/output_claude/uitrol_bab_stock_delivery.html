Na de uitrol van bab_stock_delivery

Drie handelingen, in deze volgorde. De code om te plakken staat telkens bij de stap zelf. Reken op een half uur, de droogtest inbegrepen.

Wat de uitrol meebrengt

Stocklocatie-nummering wordt een bedrijfsinstelling Nieuw vinkje Stocklocaties toekennen op het bedrijf. Enkel orders van een aangevinkt bedrijf delen nog nummers uit. Staat standaard uit.
Productenmatrix hoort op de pickbon Afdrukken kan enkel nog voor de pickstap van het eigen magazijn, en enkel als die klaar is. De omweg die daarvoor nu in de databank staat, mag weg.

Neem eerst een back-up (Odoo.sh → Backups). Stap 2 wijzigt gegevens op contacten.

1Stocklocaties aanzetten bij Vasa

Dit is de belangrijkste stap, en de enige die stil misloopt als je hem overslaat: het vinkje staat na de uitrol overal uit, dus zolang niemand het aanzet krijgt geen enkel afleveradres nog een nummer — zonder foutmelding.

  • Instellingen → Gebruikers & Bedrijven → Bedrijven → Vasa International, tabblad Algemene informatie: Stocklocaties toekennen aanvinken.
  • Bij Babimex uit laten staan. Ook bij bol.com en de retourmagazijnen, als die als apart bedrijf bestaan.

2Foute nummers opkuisen

Vanaf nu deelt Babimex geen nummers meer uit, maar de nummers die het in het verleden al opgebruikt heeft, staan er nog. Die haal je er in één keer af.

Maak een serveractie: Instellingen → Technisch → Serveracties → Nieuw.

Actienaam* Opkuis stocklocatie
ModelServeractie (ir.actions.server)
TypeCode uitvoeren, met onderstaande code
# Eenmalige opkuis van de stocklocatienummers, NA de module-uitrol en NA het
# aanvinken van "Stocklocaties toekennen" bij Vasa International.
#
# Plak dit in een SERVERACTIE (Instellingen -> Technisch -> Serveracties) met
# model "Serveractie" (ir.actions.server) en type "Code uitvoeren". Enkel met dat
# model toont Odoo 18 de knop "Uitvoeren" bovenaan het formulier.
#
# Zoals hij hier staat is het een DROOGTEST: hij telt en logt, en wijzigt niets.
# Lees het resultaat in Instellingen -> Technisch -> Logboek. Kloppen de cijfers,
# haal dan het # weg voor de laatste regel en voer opnieuw uit.
#
# Welke bedrijven nummers mogen uitdelen, wordt uit het vinkje zelf gehaald --
# geen vast bedrijfs-ID. Staat het vinkje nog nergens aan, dan doet de code
# niets en zegt hij dat; zo kan hij nooit alle nummers wissen omdat het vinkje
# vergeten werd.

companies = env['res.company'].sudo().search([('stock_location_numbering', '=', True)])
if not companies:
    log("Opkuis stocklocatie: geen enkel bedrijf heeft 'Stocklocaties toekennen' aan. "
        "Zet dat vinkje eerst bij Vasa International.", level='warning')
else:
    Order = env['sale.order'].sudo()
    # active_test=False: ook gearchiveerde afleveradressen dragen nummers, en die
    # tellen mee zodra ze ooit weer geactiveerd worden.
    Partner = env['res.partner'].sudo().with_context(active_test=False)

    numbered = Partner.search([('stock_location', '>', 0)])
    keep = Order.search([
        ('partner_shipping_id', 'in', numbered.ids),
        ('company_id', 'in', companies.ids),
    ]).mapped('partner_shipping_id')
    wrong = Order.search([
        ('partner_shipping_id', 'in', (numbered - keep).ids),
        ('company_id', 'not in', companies.ids),
    ]).mapped('partner_shipping_id')

    log("Opkuis stocklocatie: %s genummerd / %s bij %s / %s op te kuisen -- nummers: %s"
        % (len(numbered), len(keep), ", ".join(companies.mapped('name')), len(wrong),
           sorted(wrong.mapped('stock_location'))[:50]))

    # wrong.write({'stock_location': 0})

Dat model lijkt vreemd, maar Odoo 18 toont de knop Uitvoeren enkel wanneer het model op Serveractie staat en het type op code. Zo heb je geen record nodig om de actie op te draaien.

2a. Droogtest

Zoals de code in het bestand staat, telt hij enkel en wijzigt hij niets.

  • Klik Uitvoeren.
  • Lees het resultaat bovenaan Instellingen → Technisch → Logboek.

Je krijgt een regel in deze vorm:

Opkuis stocklocatie: 174 genummerd / 115 bij Vasa International / 57 op te kuisen -- nummers: [...]
  • Staat er in de plaats een waarschuwing dat geen enkel bedrijf het vinkje aan heeft, ga dan terug naar stap 1. De code doet dan bewust niets — anders zou hij álle nummers wissen omdat het vinkje vergeten werd.
  • Lijkt het aantal “op te kuisen” onwaarschijnlijk hoog (in de orde van het totaal), stop dan en laat het eerst nakijken.

2b. Echt uitvoeren

  • Haal het # weg vóór de laatste regel wrong.write({'stock_location': 0}) en sla op.
  • Klik opnieuw Uitvoeren.
  • Zet het # terug, voer nog eens uit: op te kuisen moet nu 0 zijn.
  • Verwijder de serveractie.

Welke bedrijven nummers mogen uitdelen, leest de code uit het vinkje zelf — geen vast bedrijfs-ID dat je moet opzoeken of dat kan verschillen tussen de werkkopie en productie.

3Omweg Productenmatrix opruimen

De pickbon-omweg bestaat uit vier databankrecords: een QWeb-weergave, een gekopieerde rapportactie en twee serveracties. Vanaf de uitrol zit de juiste voorwaarde in de module en zijn die overbodig — laat je ze staan, dan zie je twee keer hetzelfde in het Actie-menu.

Actienaam* Omweg Productenmatrix opruimen
ModelServeractie (ir.actions.server)
TypeCode uitvoeren, met onderstaande code
# Ruimt de databank-omweg op waarmee de Productenmatrix tot nu toe op de pickbon
# afgedrukt werd. Draai dit NA de module-uitrol: vanaf dan zit de juiste
# voorwaarde in de module zelf en is de omweg overbodig.
#
# Plak dit in een SERVERACTIE (Instellingen -> Technisch -> Serveracties) met
# model "Serveractie" (ir.actions.server) en type "Code uitvoeren", en klik
# "Uitvoeren". Twee keer draaien is veilig: de tweede keer vindt hij niets meer.
# Verwijder de serveractie nadien.
#
# De binding van de oorspronkelijke actie "* Productenmatrix (briefjes)" moet je
# NIET herstellen: die staat in de module-XML zonder noupdate, dus de uitrol zet
# ze vanzelf terug.

TEMPLATE = 'bab_stock_delivery.report_deliveryslip_matrix_pick'
weg = []

acties = env['ir.actions.server'].search([
    ('name', 'in', ['* Productenmatrix (pickbon)',
                    '* Productenmatrix (pickbon) - herdruk'])])
weg += acties.mapped('name')
acties.unlink()

rapporten = env['ir.actions.report'].search([('report_name', '=', TEMPLATE)])
weg += rapporten.mapped('name')
rapporten.unlink()

weergaven = env['ir.ui.view'].search([('key', '=', TEMPLATE)])
weg += weergaven.mapped('name')
weergaven.unlink()

log("Omweg Productenmatrix opgeruimd: %s" % (", ".join(weg) or "niets gevonden"))
  • Serveractie aangemaakt, klik Uitvoeren.
  • Controleer in het Logboek welke records verdwenen zijn — je moet er vier zien staan.
  • Verwijder de serveractie.

4Reservatierapport: de o-lijn

De o-lijn op “Productenmatrix met reservaties” toont vandaag enkel het aantal van de laatste ontvangst. Levert de leverancier in stukken, dan verspringt dat getal bij elke nieuwe bon en verdwijnt wat er eerder binnenkwam. Deze uitrol vervangt dat: de o telt dan alles op wat van de lopende aankoopbestellingen ontvangen is.

Er staat niets in de weg. Er is een tussenoplossing geprobeerd met een berekend veld op de verplaatsing, maar die is op 7 augustus 2026 weer verwijderd — ze maakte productie traag. Het veld x_ontvangst_lijnen bestaat niet meer en de weergave staat terug op die van de module. Je hoeft dus niets op te ruimen.

  • Controleer voor de zekerheid dat het veld x_ontvangst_lijnen nergens meer bestaat: Instellingen → Technisch → Databasestructuur → Velden.
  • Druk het rapport af voor een selectie Vasa-leveringen en kijk naar een variant waarvan de leverancier in twee keer geleverd heeft: de o hoort nu de som van beide ontvangsten te tonen, niet enkel de laatste bon.
  • Een variant die door meerdere klanten besteld is en op dezelfde aankooplijn staat, mag niet dubbel tellen.
  • Een variant waarvan de bestelling volledig ontvangen is, hoort nog steeds een o te tonen — via de terugval op de laatste bestelling.

5Controleren

  • Actie-menu op een overboeking: enkel nog * Productenmatrix (briefjes), geen (pickbon)-varianten meer.
  • Klare pickbon → afdrukken geeft de matrix.
  • Dezelfde pickbon nog eens → de herdrukwizard komt terug (“Productenmatrix opnieuw afdrukken?”) — die was met de omweg weggevallen.
  • Pickbon die nog niet klaar is → melding not done yet.
  • Uitgaande levering → melding not a pick transfer.
  • Vasa-order bevestigen op een nieuw afleveradres → het krijgt een nummer in zijn landreeks.
  • Babimex-order bevestigen op een nieuw afleveradres → blijft op 0.

Wat vanzelf goed komt

  • De binding van * Productenmatrix (briefjes) — die is bij het opzetten van de omweg weggehaald, maar staat in de module-XML zonder noupdate, dus de uitrol zet ze terug. Je hoeft daar niets voor te doen; stap 4 controleert het.
  • De weergave van het reservatierapport — de aangepaste architectuur van report_reservation_matrix wordt door de uitrol overschreven met die van de module. Enkel het berekende veld moet je zelf weghalen, zie stap 4.
  • De herdruk-bevestigingswizard — die werkt weer zodra het afdrukken via de module-actie loopt.

Er staat in productie geen automatiseringsregel voor de stocklocaties: die tussenoplossing is nooit uitgerold. Je hoeft dus niets te verwijderen — het vinkje uit stap 1 plus de opkuis uit stap 2 volstaan.
