Leveradres-veld op de batch + op de PDF

BAB · Odoo 18.0 · stock.picking.batch + rapport report_picking_batch · genoteerd 2026-06-26

Doel

Op de batchpicking het volledige leveradres tonen i.p.v. enkel de klantnaam. Vandaag staat op de PDF in de kop een regel Klant: die het standaardveld description toont (de losse klantnaam, een samenvoegsel als een batch meerdere klanten zou bevatten). Bij BAB is een batch altijd per klant, dus we vervangen die waarde door het volledige adres van het leveradres van de eerste picking in de batch, en we hernoemen het label naar Leveradres (op het formulier én op de PDF).

Resultaat in de kop van de batch-PDF — de bestaande regels Sluitingsdagen en Leverinformatie blijven ongewijzigd:

Leveradres:  Annebel Londerzeel
             Handelsstraat 44
             1840 Londerzeel
Sluitingsdagen:  Maandagvoormiddag gesloten
Leverinformatie: …

Wat we toevoegen

OnderdeelWat
Nieuw veldBerekend, opgeslagen tekstveld x_studio_delivery_address op stock.picking.batch — bouwt het adres uit het leveradres (partner_id) van de eerste picking.
FormulierHet veld zichtbaar maken op de batch (rechterkolom, bij de andere x_studio_* velden), label Leveradres.
PDF-rapportIn de bestaande kop-aanpassing: het veld in de Klant:-regel veranderen van o.description naar het nieuwe veld, en het label Klant: → Leveradres: (op beide kopblokken — pagina 1 én pagina 2).

Compute-code

Neemt de eerste picking (gesorteerd op batch_sequence, net als het rapport) en bouwt het adresblok van diens leveradres. Land enkel als het niet België is.

for record in self:
    pickings = record.picking_ids.sorted('batch_sequence')
    partner = pickings[:1].partner_id
    lines = []
    if partner:
        if partner.name:
            lines.append(partner.name)
        if partner.street:
            lines.append(partner.street)
        if partner.street2:
            lines.append(partner.street2)
        city = ((partner.zip or '') + ' ' + (partner.city or '')).strip()
        if city:
            lines.append(city)
        if partner.country_id and partner.country_id.code != 'BE':
            lines.append(partner.country_id.name)
    record['x_studio_delivery_address'] = '\n'.join(lines)

Geen lambda in de sort. De compute draait via safe_eval — gebruik .sorted('batch_sequence') (veldnaam als string), niet .sorted(lambda p: …).

B1 · Veld + herberekenen + formulier (odoo-bin shell)

In odoo-bin shell op de productie-DB. Maakt het veld, herbouwt de registry, berekent alle batches en registreert het als Studio-veld:

MODEL = 'stock.picking.batch'
FNAME = 'x_studio_delivery_address'
COMPUTE = """for record in self:
    pickings = record.picking_ids.sorted('batch_sequence')
    partner = pickings[:1].partner_id
    lines = []
    if partner:
        if partner.name:
            lines.append(partner.name)
        if partner.street:
            lines.append(partner.street)
        if partner.street2:
            lines.append(partner.street2)
        city = ((partner.zip or '') + ' ' + (partner.city or '')).strip()
        if city:
            lines.append(city)
        if partner.country_id and partner.country_id.code != 'BE':
            lines.append(partner.country_id.name)
    record['x_studio_delivery_address'] = '\n'.join(lines)
"""
DEPENDS = ('picking_ids,picking_ids.batch_sequence,picking_ids.partner_id,'
           'picking_ids.partner_id.name,picking_ids.partner_id.street,'
           'picking_ids.partner_id.street2,picking_ids.partner_id.zip,'
           'picking_ids.partner_id.city,picking_ids.partner_id.country_id')

IMF = env['ir.model.fields']
if not IMF.search([('model','=',MODEL),('name','=',FNAME)]):
    IMF.create({
        'model_id': env['ir.model']._get_id(MODEL),
        'model': MODEL, 'name': FNAME, 'field_description': 'Leveradres',
        'ttype': 'text', 'state': 'manual', 'store': True, 'readonly': True,
        'compute': COMPUTE, 'depends': DEPENDS,
    })
env.cr.commit()

# registry + kolom opbouwen, dan herberekenen
env.registry.setup_models(env.cr)
env.registry.init_models(env.cr, [MODEL], {'update_custom_fields': True})
env.cr.commit()
from odoo import api, SUPERUSER_ID
env = api.Environment(env.cr, SUPERUSER_ID, {})
Batch = env[MODEL]
batches = Batch.search([])
env.add_to_compute(Batch._fields[FNAME], batches)
batches.flush_recordset([FNAME])
# als Studio-veld registreren (zodat het in de Studio-export zit)
env['ir.model.fields'].search([('model','=',MODEL),('name','=',FNAME)]) \
    .with_context(studio=True).create_studio_model_data(FNAME)
env.cr.commit()
print('klaar:', len(batches), 'batches')

Het veld op het formulier zetten doe je het makkelijkst alsnog in Studio (A2). Wil je het toch via de DB: voeg in de Studio-form-inherit een <xpath … position="inside"><field name="x_studio_delivery_address"/></xpath> toe in de rechter groep.

B2 · De PDF (zoek de view op, dan aanpassen)

Zoek eerst de Studio-inherit van het batchrapport (die met Klant:):

SELECT v.id
FROM ir_ui_view v
JOIN ir_ui_view base ON base.id = v.inherit_id
WHERE base.key = 'stock_picking_batch.report_picking_batch'
  AND v.arch_db::text LIKE '%o.description%';

Wissel in die view (vervang <ID> door het resultaat) het veld én het label, op alle talen die ingevuld zijn — in de praktijk staat de Studio-arch in en_US:

UPDATE ir_ui_view
SET arch_db = jsonb_set(arch_db, '{en_US}', to_jsonb(
    replace(
      replace(arch_db->>'en_US',
        '<span t-field="o.description"/>',
        '<span t-field="o.x_studio_delivery_address"/>'),
      '<strong>Klant:</strong>',
      '<strong>Leveradres:</strong>')))
WHERE id = <ID>;

Na een rauwe SQL-view-edit moet de server zijn cache lossen. Op Odoo.sh: herstart de instance (of upgrade/refresh). Bij Pad A (Studio) gebeurt dit automatisch.

Verifiëren

Render de PDF server-side voor één batch en kijk of de kop het adres toont (in odoo-bin shell):

b = env['stock.picking.batch'].search([('x_studio_delivery_address','!=',False)], limit=1)
html, _ = env['ir.actions.report'].with_context(lang='nl_BE') \
    ._render_qweb_html('stock_picking_batch.report_picking_batch', b.ids)
html = html.decode() if isinstance(html, bytes) else html
print('Leveradres:' in html, '|', b.x_studio_delivery_address)

Of gewoon: open een batch in de UI → Afdrukken → Batchepicking en controleer de kop. Een paar batches met een straat/postcode geven het beste beeld.

Terugdraaien

  • PDF: draai de UPDATE uit B2 om (label en veld terug naar Klant: / o.description), of herstel de regel in Studio.
  • Veld: verwijder het via Studio (Velden-lijst) of env['ir.model.fields'].search([('model','=','stock.picking.batch'),('name','=','x_studio_delivery_address')]).unlink(). Dat dropt de kolom; controleer dat de PDF eerst weer o.description gebruikt, anders rendert het rapport een onbekend veld.

Aandachtspunten

  • Eén klant per batch. De aanname is dat een BAB-batch per klant is. Mengt een batch ooit klanten, dan toont het veld enkel het adres van de eerste picking — het breekt niet, maar is dan onvolledig.
  • Leveradres = partner_id van de picking. Op een uitgaande levering is dat het ship-to-adres — net het adres dat vandaag al de Klant:-naam voedt.
  • Meerregelig op de PDF. Een Text-veld met t-field rendert \n automatisch als <br/> (nl2br). Geen extra opmaak nodig.
  • Label-talen. Op de PDF is het label vaste tekst per taal in de Studio-arch; in een nl_BE-only afdruk volstaat Leveradres:. De andere talen (en/fr/de) hoef je enkel te vertalen als je die effectief afdrukt.
  • description blijft bestaan. We laten het standaardveld staan (nog bruikbaar als korte identifier op het formulier); enkel zijn rol in de PDF-kop is overgenomen door het adres.
